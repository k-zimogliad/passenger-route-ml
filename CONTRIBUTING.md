# Правила работы с кодом

Проект «ПассажирМаршрут». Правила обязательны для всех участников. Если правило в чате расходится с этим файлом, верно то, что написано здесь. Любое изменение правил вносится через Pull Request и сообщается в общем чате.

## 1. Данные и выборки

1. Названия полей и значения категорий (`deck`, `briefing`) записаны в `DATA.md`. Менять их можно только по общему решению, об изменении сообщается в общем чате.
2. Разбиение 60/20/20 со стратификацией делает участник 1 один раз с фиксированным `seed`. Выборки называются только `train`, `val`, `test`.
3. Скрытые переменные (время, скорость, задержка) хранятся в отдельном файле и в модели не передаются.
4. Для итоговых экспериментов используется только зафиксированная версия генератора v2. Пробные данные лежат отдельно, метрики для отчёта с них не берутся.

## 2. Предобработка и модели

5. Предобработка одна на всех. Метод `fit` вызывается только на обучающей выборке, к `val` и `test` применяется только `transform`.
6. Метрики считает общий модуль: `balanced_accuracy`, `accuracy`, `confusion_matrix`.
7. Функции обучения моделей принимают список признаков и `random_state` как параметры.
8. Во всех запусках задан `random_state`.
9. Есть короткие тесты: предобработка не использует данные `val` и `test`, метрики считаются верно.

## 3. Валидация и тест

10. Подбор параметров, сравнение моделей и абляция проводятся только на `val`.
11. Правило выбора финальной модели записывается в `EXPERIMENTS.md` с датой до открытия теста.
12. Тест запускается один раз. После этого модели, генератор и правила не меняются.

## 4. Результаты

13. Метрики, таблицы и прогнозы сохраняются в папку `results/`. Числа в отчёты берутся из этих файлов, а не переписываются вручную.
14. Каждый эксперимент кратко записывается в `EXPERIMENTS.md`: что запускали, с какими параметрами, какой результат.
15. Есть один скрипт полного запуска проекта и файл `requirements.txt` с версиями библиотек.

## 5. Имена

16. Файлы, переменные, функции и колонки называются латиницей в `snake_case`. Русский язык используется только в документах (`.md`, `.txt`).
17. Названия моделей: `baseline_majority`, `logreg`, `tree_d3`, `tree_d5`, `tree_dnone`. Если есть дополнительные параметры, они дописываются в конец (например, `tree_d3_leaf20`).
18. Названия метрик: `balanced_accuracy`, `accuracy`, `confusion_matrix`.
19. Переменные: `df_train`, `df_val`, `df_test` для таблиц; `X_train`, `y_train`, `X_val`, `y_val`, `X_test`, `y_test` для признаков и цели. Константы пишутся заглавными буквами: `RANDOM_STATE`, `TARGET`.
20. Единые интерфейсы:
    - `Preprocessor.fit(df)` и `Preprocessor.transform(df)`;
    - `compute_metrics(y_true, y_pred)`;
    - `train_<модель>(df_train, features, params, random_state)`.
21. Названия файлов:
    - `data/raw/passengers_v2_seed42.csv` (версия генератора и `seed` в имени);
    - `data/splits/train.csv`, `val.csv`, `test.csv`;
    - `results/predictions/<модель>_<выборка>.csv` с колонками `id`, `y_true`, `y_pred`, `model`;
    - `results/figures/p<номер участника>_<название>.png`.
22. Общие названия колонок, целевой переменной, списков признаков, `RANDOM_STATE` и путей лежат в одном файле `src/constants.py`, и все импортируют их оттуда.

## 6. Работа в репозитории

23. У каждого участника своя ветка: `p1-data`, `p2-preprocess-logreg`, `p3-trees`, `p4-evaluation`. В `main` изменения вносятся только через Pull Request, лучше небольшими частями. Чужие файлы без согласования не правятся.
24. Сообщения коммитов начинаются с номера участника, например: `p3: add depth curve plot`.

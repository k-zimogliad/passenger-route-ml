# GENERATOR.md

## Назначение

Этот файл описывает, как устроен генератор синтетических данных для темы **«ПассажирМаршрут»** и что означает каждая часть `config/generator.yaml`.

Главная идея такая:

- `src/constants.py` хранит **имена колонок, списки признаков, пути и `RANDOM_STATE`**;
- `config/generator.yaml` хранит **настройки генерации**: размеры выборки, распределения, шумы, порог времени и параметры скрытой модели.

## Общая структура `generator.yaml`

```yaml
dataset:
  ...

distributions:
  ...

hidden_model:
  ...

derived:
  ...
```

### Что означает каждый верхний ключ

- `dataset` — параметры набора данных: размер, seed, доля пропусков.
- `distributions` — как генерируются наблюдаемые признаки.
- `hidden_model` — скрытая формула, по которой считается время и целевой класс.
- `derived` — правило перевода скрытого результата в ответ модели.

## `dataset`

```yaml
dataset:
  n_samples: 3000
  age_missing_rate: 0.05
  seed: 42
```

### `n_samples: 3000`

Размер основного набора. В основной карточке проекта для «ПассажирМаршрут» задано **3000 независимых вымышленных наблюдений**.

### `age_missing_rate: 0.05`

Доля строк, где значение `age` скрывается пропуском. Это соответствует требованию проекта: в 5% строк случайно скрывается возраст.

### `seed: 42`

Фиксированный seed для воспроизводимости. При одинаковом seed генератор должен выдавать одинаковый результат.

## `distributions`

Этот раздел отвечает за **видимые признаки**.

### `age`

```yaml
age:
  kind: truncated_uniform
  low: 18
  high: 80
```

- `kind` — режим генерации.
- `truncated_uniform` — равномерное распределение на отрезке с ограничением по границам.
- `low: 18` — нижняя граница возраста.
- `high: 80` — верхняя граница возраста.


Смысл: возраст должен быть в разумном диапазоне, без редких экстремальных значений.

### `deck`

```yaml
deck:
  values: [lower, middle, upper]
  probs: [0.41, 0.21, 0.38]
```

- `values` — допустимые категории палуб.
- `probs` — вероятности этих категорий.

Здесь палуба задаётся как категориальный признак с тремя уровнями. Вероятности не равны: это создаёт немного более естественное распределение и позволяет палубе влиять на данные, не делая задачу тривиальной.

### `distance_m`

```yaml
distance_m:
  kind: truncated_normal_by_deck
  lower:  {mean: 166, std: 45, low: 20, high: 300}
  middle: {mean: 137, std: 45, low: 20, high: 300}
  upper:  {mean: 157, std: 50, low: 20, high: 300}
```

- `kind: truncated_normal_by_deck` — усечённое нормальное распределение, параметры зависят от `deck`.
- `mean` — среднее расстояние для конкретной палубы.
- `std` — разброс расстояний.
- `low` / `high` — допустимые границы.

Смысл: палуба влияет на длину маршрута, но не определяет её однозначно. Значения для разных палуб пересекаются, поэтому модель не может просто по `deck` восстановить `distance_m` без ошибок.

### `luggage_count`

```yaml
luggage_count:
  values: [0, 1, 2, 3]
  probs: [0.25, 0.24, 0.24, 0.27]
```

- `values` — допустимое число предметов багажа.
- `probs` — вероятность каждого значения.

Это дискретный категориально-числовой признак. Он нужен как фактор, который влияет на задержку и скорость.

### `briefing`

```yaml
briefing:
  values: [0, 1]
  probs: [0.45, 0.55]
```

- `0` — инструктаж не пройден.
- `1` — инструктаж пройден.

Это бинарный признак. Он должен быть достаточно частым, чтобы его влияние можно было увидеть в данных.

## `hidden_model`

Этот раздел описывает **скрытую модель времени**. Именно здесь находятся величины, которые не попадают в признаки для обучения, но используются внутри генератора.

### `speed`

```yaml
speed:
  base_mps: 1.35
  age_slope_per_year: -0.003
  deck_bonus_mps:
    lower: -0.08
    middle: 0.00
    upper: 0.10
  luggage_penalty_mps: 0.04
  briefing_bonus_mps: 0.03
  noise_std_mps: 0.05
```

- `base_mps` — базовая скорость в метрах в секунду.
- `age_slope_per_year` — линейное влияние возраста на скорость.
- `deck_bonus_mps` — поправка на палубу.
- `luggage_penalty_mps` — штраф за багаж.
- `briefing_bonus_mps` — бонус от инструктажа.
- `noise_std_mps` — случайный шум скорости.

Смысл: скорость получается как сумма базового уровня, линейных поправок и шума. Это и есть пример линейной зависимости внутри скрытой модели.

### `start_delay_sec`

```yaml
start_delay_sec:
  base: 18
  age_slope_per_year: 0.08
  luggage_penalty_per_bag: 8
  briefing_bonus: -6
  noise_std: 3
```

- `base` — базовая задержка перед стартом.
- `age_slope_per_year` — рост задержки с возрастом.
- `luggage_penalty_per_bag` — добавка за каждый предмет багажа.
- `briefing_bonus` — уменьшение задержки после инструктажа.
- `noise_std` — шум задержки.

Смысл: пассажир не начинает движение мгновенно. У одних старт быстрее, у других медленнее.

### `random_delay_sec`

```yaml
random_delay_sec:
  mean: 8
  std: 3
```

Дополнительная случайная задержка в пути.

- `mean` — среднее значение задержки.
- `std` — разброс.

Она нужна, чтобы два пассажира с очень похожими признаками не имели абсолютно одинаковое время прибытия.

### `time_limit_sec`

```yaml
time_limit_sec: 180
```

Порог времени в секундах. Если `total_time_sec` не превышает этот лимит, пассажир считается успевшим.

## `derived`

Этот раздел описывает, как из скрытого времени получается целевой класс.

```yaml
derived:
  arrival_rule: "1 if total_time_sec <= time_limit_sec else 0"
  total_time_components: [start_delay_sec, travel_time_sec, random_delay_sec]
```

### `arrival_rule`

Текстовое правило перевода времени в класс:

- `1`, если время не больше лимита;
- `0`, если время больше лимита.

Это пороговая зависимость.

### `total_time_components`

Список компонентов, из которых складывается итоговое время:

- `start_delay_sec`
- `travel_time_sec`
- `random_delay_sec`

## Как это использовать в коде

Обычно схема такая:

1. Прочитать YAML через `yaml.safe_load`.
2. Из `dataset` взять размер выборки, seed и долю пропусков.
3. Сгенерировать видимые признаки из `distributions`.
4. Посчитать скрытые величины из `hidden_model`.
5. По правилу из `derived` получить `arrived_in_time`.
6. Сохранить в итоговый CSV только видимые признаки и target.
7. Скрытые величины сохранить отдельно в debug-файл.

## Что не должно дублироваться в YAML

В YAML не нужно повторять:

- названия колонок;
- пути к файлам;
- списки признаков для моделей;
- `RANDOM_STATE` и другие общие константы.

Это уже хранится в `src/constants.py`.

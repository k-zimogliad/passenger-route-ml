# Правила работы с кодом и репозиторием

Здесь установлены единые стандарты разработки для команды проекта «ПассажирМаршрут». Соблюдение правил обеспечивает совместимость программных модулей, корректность валидации и воспроизводимость результатов. Любые изменения правил вносятся через Pull Request после согласования с командой.

## 1. Данные и выборки

1. Названия полей и допустимые значения категорий (`deck`, `briefing`) зафиксированы в `DATA.md`. Изменять их можно только по общему решению команды с уведомлением в чате.
2. Стратифицированное разбиение 60/20/20 выполняет участник 1 один раз с фиксированным `seed`. Выборочные наборы называются строго `train`, `val`, `test`.
3. Скрытые переменные генератора (истинная скорость, задержка, время прибытия) сохраняются в отдельный файл и ни при каких условиях не передаются моделям.
4. Для основных экспериментов используется только зафиксированная версия генератора `v2`. Пробные наборы данных хранятся отдельно и не используются для расчёта итоговых метрик в отчётах.

## 2. Предобработка и модели

5. Модуль предобработки (`Preprocessor`) единый для всех моделей. Метод `fit` вызывается исключительно на обучающей выборке; к `val` и `test` применяется только `transform`.
6. Перед итоговой проверкой на `test` предобработчик и выбранная модель заново обучаются (`fit`) на объединённой выборке `train + val`.
7. Все метрики рассчитываются через единый модуль: `balanced_accuracy`, `accuracy`, `confusion_matrix`.
8. Функции обучения моделей принимают список используемых признаков и `random_state` в качестве явных параметров.
9. Во всех стохастических операциях (разбиение, генерация, обучение деревьев) фиксируется `random_state`.
10. Для ключевых модулей пишутся короткие автоматические тесты: проверка отсутствия утечки данных из `val` и `test` при предобработке и проверка корректности расчёта метрик.

## 3. Валидация и итоговый тест

11. Подбор гиперпараметров, сравнение моделей и абляция признаков проводятся только на валидационной выборке (`val`).
12. Правило выбора финальной модели фиксируется в `EXPERIMENTS.md` с указанием даты до первого запуска на тестовой выборке.
13. Итоговая оценка на `test` выполняется один раз. После открытия тестовых результатов менять генератор, предобработку, признаки или гиперпараметры моделей запрещено.

## 4. Результаты и воспроизводимость

14. Все таблицы метрик, прогнозы и графики сохраняются в директорию `results/`. Числовые значения в отчёты переносятся из сохранённых файлов, а не вычисляются вручную.
15. Каждый проведённый эксперимент кратко документируется в `EXPERIMENTS.md`: конфигурация, параметры запуска и полученные метрики.
16. Все скрипты запускаются из корня репозитория как модули (`python -m src.<имя_модуля>`), чтобы исключить ошибки относительных импортов.
17. В коде используются только относительные пути (через `pathlib.Path`) и кодировка `UTF-8` при чтении и записи файлов.
18. В репозитории должен быть единый скрипт полного воспроизведения результатов (`src/run_all.py`) и актуальный файл зависимостей `requirements.txt` с зафиксированными версиями библиотек.

## 5. Единые константы, имена и интерфейсы

19. Все общие названия колонок, целевой переменной, списки признаков, значение `RANDOM_STATE` и пути к файлам хранятся в одном месте — `src/constants.py`. Участники импортируют их оттуда и не дублируют строками в своих модулях:

```python
from src.constants import (
    RANDOM_STATE,
    ID_COL,
    TARGET_COL,
    NUM_FEATURES,
    CAT_FEATURES,
    ALL_FEATURES,
    REDUCED_FEATURES,
    TRAIN_PATH,
    VAL_PATH,
    TEST_PATH,
)
```

20. Имена файлов, переменных, функций и колонок датасета пишутся на английском языке в формате `snake_case`. Русский язык используется в документации (`.md`, `.txt`), а также допускается в комментариях и `docstrings` внутри кода.
21. Стандартные имена моделей: `baseline_majority`, `logreg`, `tree_d3`, `tree_d5`, `tree_dnone`. Дополнительные параметры дописываются в конец названия (например, `tree_d3_leaf20`).
22. Стандартные имена метрик: `balanced_accuracy`, `accuracy`, `confusion_matrix`.
23. Стандартные имена переменных: `df_train`, `df_val`, `df_test` для таблиц; `X_train`, `y_train`, `X_val`, `y_val`, `X_test`, `y_test` для матриц признаков и целевого вектора. Константы оформляются в верхнем регистре (`RANDOM_STATE`, `TARGET_COL`).
24. Обязательные сигнатуры общих интерфейсов:
    - `Preprocessor.fit(df)` и `Preprocessor.transform(df)`;
    - `compute_metrics(y_true, y_pred)`;
    - `train_<модель>(df_train, features, params, random_state)`.
25. Соглашение об именовании выходных файлов:
    - `data/raw/passengers_v2_seed42.csv` (версия генератора и `seed` в имени);
    - `data/splits/train.csv`, `val.csv`, `test.csv`;
    - `results/predictions/<модель>_<выборка>.csv` с колонками `passenger_id`, `y_true`, `y_pred`, `model`;
    - `results/figures/p<номер_участника>_<название>.png`.

## 6. Работа в Git-репозитории

26. Каждый участник работает в своей ветке, ответвленной от `main`:
    - Участник 1: `p1-data`
    - Участник 2: `p2-preprocess-logreg`
    - Участник 3: `p3-trees`
    - Участник 4: `p4-evaluation`
27. Прямые коммиты в `main` запрещены. Изменения вливаются только через Pull Request после проверки хотя бы одним участником команды. Перед созданием PR необходимо подтянуть актуальные изменения из `main` в свою ветку. Чужие модули без предварительного согласования не правятся.
28. Сообщения коммитов начинаются с префикса участника, например: `p3: add depth curve plot`.
29. Служебные файлы IDE (`.vscode/`, `.idea/`), кэш Python (`__pycache__/`) и виртуальные окружения (`venv/`, `.venv/`) добавляются в `.gitignore` и не загружаются в репозиторий.

## 7. Структура репозитория

В квадратных скобках указан номер ответственного участника.

```text
passenger-route-ml/
├── README.md                  # инструкция запуска, структура, состав команды     [4; раздел про данные: 1]
├── CONTRIBUTING.md            # правила работы с кодом и репозиторием
├── DOMAIN.md                  # предметная область, допущения                     [1]
├── GENERATOR.md               # правила генерации, признаки, целевая переменная   [1]
├── DATA.md                    # схема полей, категории, проверки, размеры выборок [1]
├── EXPERIMENTS.md             # журнал экспериментов и правило выбора модели      [все; правило: 4]
├── requirements.txt           # библиотеки с зафиксированными версиями            [4]
├── .gitignore                 # исключения Git для Python и IDE
│
├── config/
│   └── generator.yaml         # параметры генератора, seed, доля пропусков        [1]
│
├── src/
│   ├── constants.py           # колонки, цель, списки признаков, RANDOM_STATE, пути [1, 2]
│   ├── generate.py            # генератор синтетических данных                    [1]
│   ├── split.py               # стратифицированное разбиение 60/20/20             [1]
│   ├── preprocess.py          # общий Preprocessor (fit/transform)                [2]
│   ├── metrics.py             # balanced_accuracy, accuracy, confusion_matrix     [2]
│   ├── logreg.py              # логистическая регрессия                           [2]
│   ├── trees.py               # деревья решений                                   [3]
│   ├── baseline.py            # базовый классификатор (самый частый класс)        [4]
│   ├── ablation.py            # абляция признаков                                 [4]
│   ├── evaluate.py            # протокол итоговой оценки, тест, анализ ошибок     [4]
│   └── run_all.py             # скрипт полного воспроизведения проекта            [4]
│
├── tests/
│   ├── test_generator.py      # граница лимита, диапазоны, воспроизводимость seed [1]
│   ├── test_preprocess.py     # отсутствие утечки, fit только на train            [2]
│   ├── test_metrics.py        # корректность расчёта метрик                       [2]
│   └── test_pipeline.py       # стыковка разбиения, предобработки и метрик        [4]
│
├── data/
│   ├── raw/
│   │   ├── passengers_v2_seed42.csv          # основной датасет для моделей       [1]
│   │   └── passengers_v2_seed42_hidden.csv   # скрытые переменные (не для моделей)  [1]
│   ├── trial/                 # пробный набор для отладки и калибровки            [1]
│   └── splits/
│       ├── train.csv
│       ├── val.csv
│       └── test.csv                                                               [1]
│
└── results/
    ├── eda/                   # графики и таблицы первичного анализа              [1]
    ├── validation/            # метрики и графики регрессии и деревьев            [2, 3]
    ├── ablation/              # таблица результатов абляции                       [4]
    ├── predictions/           # <модель>_<выборка>.csv (passenger_id, y_true, y_pred, model) [2, 3, 4]
    ├── test/                  # итоговая таблица, матрица ошибок, разбор ошибок   [4]
    └── figures/               # графики с префиксом p<номер>_                     [все]
```
